# Story 0.0.2: Error handling and fixture data match real production shapes and volumes

Status: ready-for-dev

## Story

As the **engineer building the nightly JOH data sync**,
I want the practice copy to return error messages in exactly the same shape as the real system, and to be seeded with test data at a realistic scale,
so that the sync's error handling is proven against real error formats, and its behaviour is checked against realistic data volumes rather than a handful of hand-picked test records.

## Acceptance Criteria

1. Given the practice copy is asked for something without a piece of information it needs, when a request is missing a required date, or gives an invalid or unrecognised lookup value, then the response comes back with the confirmed error-message format, clearly explaining what went wrong.
2. Given the practice copy's seeded test data, when the automated test suite starts up, then the lookup data is seeded at the same scale as the real system (matching real-world counts for locations, job titles, roles, tickets, and categories).
3. The generated people records are internally consistent — their appointments, roles, and permissions all line up with the same seeded lookup data, rather than being randomly generated in isolation.

## Tasks / Subtasks

- [ ] Task 1 — Confirmed error shape for a missing required date (AC: 1)
  - [ ] Write the failing test: `GET /api/v5/people` (and `/leavers`, `/deleted`) with no from-date parameter expects the confirmed error-message shape; run; capture red (R2, T1)
  - [ ] Minimum implementation to pass; re-run; capture green
- [ ] Task 2 — Confirmed error shape for an invalid or unrecognised lookup value (AC: 1)
  - [ ] Write the failing test: `GET /api/v5/reference_data/:attribute_name` with an unrecognised `attribute_name`, and `.../:reference_id` with an unrecognised id, each expecting the confirmed error shape; run; capture red
  - [ ] Minimum implementation to pass; re-run
  - [ ] Parameterised-test sweep (T11) across the malformed-input cases the real API's Swagger/example payloads document, one named case per input, not a loop
- [ ] Task 3 — Seed lookup data at real production scale (AC: 2)
  - [ ] Write the failing test asserting seeded row counts match the confirmed real-world counts (`locations`: 2000, `base_locations`: 1462, `appointment_titles`: 194, `judiciary_roles`: 164, `tickets`: 159, `ticket_categories`: 54, plus the small fixed vocabularies `genders`/`contract_types`/`location_types`/`ticket_category_types`/`jurisdictions`); run; capture red
  - [ ] Build the seeding routine (test-data builder per T14, not inline construction) to pass; re-run
- [ ] Task 4 — Internally-consistent generated person records (AC: 3)
  - [ ] Write the failing test: a generated person's appointment, role, and ticket references all resolve against the seeded lookup tables from Task 3 (no dangling reference to a lookup value that was never seeded); run; capture red
  - [ ] Build the person-record generator to draw from the seeded lookup set (not independent randomisation) to pass; re-run

Do not default to CTAM's `application/problem+json` shape for the mock's error bodies — pin the actual shape to the real Swagger export / example payloads this story was scoped against, per the same R4/R5 caveat as 0.0.1.
- [Source: `_arch/architecture/gaps.md#g8-1`] confirms, at `bus_version: arch-v1.1`, that the real-world seed counts this story's AC-2 requires (2000 locations, 1462 base locations, 194 appointment titles, 164 judiciary roles, 159 tickets, 54 ticket categories) are **not yet reflected on the bus** — G8.1 at this pin still reads the eLinks contract as unconfirmed and does not carry these counts. They come from the control-plane repo's own record of this work (`ctam-analysis`'s `_bmad-output/planning-artifacts/architecture/gaps.md`, entry **G8.7**, dated 2026-08-20), which had not yet been republished to the architecture bus as of this packet's `bus_version`. Treat the counts above as the authoritative figures for this story, but flag in the handoff that they are sourced from the control-plane repo rather than `_arch`, in case a later bus republish changes them.
- [Source: `_arch/architecture/data-tables.md#tier-a--joh-elinks-upstream-sourced--15-tables`] — the lookup-category tables (`jo_appointment_titles`, `jo_base_locations`, `jo_judiciary_roles`, `jo_tickets`, `jo_ticket_categories`, `jo_locations`, etc.) this task's seed volumes correspond to.
