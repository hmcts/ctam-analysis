# Story 1.0.3: The shared database and secrets vault are built and checked (development environment)

Status: ready-for-dev

## Story

As a **platform engineer**,
I want a shared PostgreSQL database and a secrets vault built through Terraform, with the cluster wired up to read from the vault securely,
so that **services have an encrypted, secure shared database and a safe place to keep secrets — proven reachable and working from inside the cluster before any service actually needs them**.

## Acceptance Criteria

1. Given the cluster exists as described in Story 1.0.2, when the engineer adds the database and vault setup and applies it to the development environment, a PostgreSQL database is provisioned with a resilient, zone-spread setup, with its stored data encrypted at rest.
2. The database is set up so that only encrypted connections are accepted and any unencrypted connection attempt is refused.
3. A secrets vault is provisioned with protections against accidental or malicious permanent deletion.
4. The cluster is configured so that workloads running on it can securely read secrets from the vault without needing a stored password of their own.
5. No database or vault secrets are ever committed into the repository — everything sensitive lives only in the vault.
6. Given the database and vault have been built, when the engineer runs the verification from a workload running inside the cluster, an encrypted connection to the database succeeds, and an unencrypted connection attempt is correctly refused.
7. A scratch database can be created and then removed again, confirming basic connectivity and permissions work as expected.
8. A test secret written into the vault can be successfully read back by the workload using its secure identity, confirming the secret-reading setup genuinely works.
9. These checks are written down as repeatable verification steps.

## Tasks / Subtasks

- [ ] Task 1 (AC: 1, 2): Write `terraform/modules/postgres/` (Flexible Server, zone-redundant HA, encryption at rest, TLS-enforced connection policy). Capture a red `verification/postgres-tls.sh` run before apply (no server to connect to), then apply and capture green.
- [ ] Task 2 (AC: 3): Write `terraform/modules/keyvault/` with soft-delete and purge protection enabled.
- [ ] Task 3 (AC: 4): Wire AKS workload identity federation to the vault so pods authenticate without a stored client secret.
- [ ] Task 4 (AC: 5): Confirm no `.tfvars`, no state file, and no output value containing a raw secret is committed; secrets flow only through the vault.
- [ ] Task 5 (AC: 6, 7, 9): Write `verification/postgres-tls.sh` — from a workload inside the cluster, prove TLS connect succeeds, plaintext connect is refused, and a scratch database can be created and dropped. Paste the red run (before the module exists) and the green run (after).
- [ ] Task 6 (AC: 8, 9): Write `verification/keyvault-roundtrip.sh` — write a test secret, read it back from a workload using its workload identity. Paste red/green evidence.
