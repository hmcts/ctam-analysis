# Story 1.0.1: The shared repository and its safe change-management process are set up

Status: ready-for-dev

## Story

As a **platform engineer**,
I want the dedicated `ctam-shared-infrastructure` repository set up correctly from day one, with a working way to safely store and track infrastructure changes, separate setups per environment, and an automated pipeline that checks and applies changes,
so that **the shared estate has a proper home with safe, reviewed, tracked change management before a single piece of it is actually built**.

## Acceptance Criteria

1. The manual GitHub setup checklist is completed before any Terraform work starts: the `ctam-shared-infrastructure` repository is created under the HMCTS organisation through the GitHub website, following the standard naming pattern for shared programme infrastructure.
2. Branch protection is turned on for `main` (pull-request review required, automated checks required, linear history required).
3. `CODEOWNERS` is set up so changes are routed to the platform/infrastructure team.
4. All of the above GitHub setup is done by hand through the website, following the documented runbook — the `gh` command-line tool is not available, so none of it is scripted.
5. The repository contains separate folders for the development, staging, and production environments, each with pinned versions of the Azure provider it uses.
6. A remote, shared place to safely store the infrastructure's tracked state is configured (an Azure Storage account and container, following the agreed pattern).
7. An automated check runs on every pull request that formats and validates the Terraform code and previews what it would change.
8. A separate, gated step applies changes only once code is merged into `main`, per environment, requiring a manual approval step for staging and production.
9. A code-ownership file and a pull-request checklist template both exist to guide reviewers.
10. With the Terraform structure in place but nothing actually built yet, opening a pull request makes the validation check pass and the preview show a clean, empty result (nothing to change).
11. Once merged, an empty "apply" run against the development environment succeeds and safely records that nothing has been built yet.
12. The whole run is visible in the pipeline logs, with the preview output attached to the pull request for reviewers to see.

## Tasks / Subtasks

- [ ] Task 1 (AC: 1, 2, 3, 4): Work through the documented GitHub runbook by hand — create the repo under the HMCTS org, turn on branch protection for `main` (PR review + required checks + linear history), add `CODEOWNERS` routing to the platform/infra team. No `gh` CLI usage anywhere in this task.
- [ ] Task 2 (AC: 5): Lay down `terraform/dev/`, `terraform/staging/`, `terraform/production/` with a pinned `azurerm` provider version in each. Run `terraform validate` against the empty scaffold first and capture the failure (missing backend / no provider config) as the red evidence, then add the minimum provider/backend block to go green.
- [ ] Task 3 (AC: 6): Provision the remote state backend (Azure Storage account + container) and wire `backend "azurerm" {}` into each environment folder. Verify with `terraform init` per environment; capture the output.
- [ ] Task 4 (AC: 7, 10): Author `.github/workflows/ci.yml` running `terraform fmt -check`, `terraform validate`, and `terraform plan` on every PR. Open the first PR against the empty scaffold to capture a red run (e.g. an intentional fmt violation or missing backend config), fix it, then capture the clean, empty-plan green run — paste both per R2/R12.
- [ ] Task 5 (AC: 8): Author `.github/workflows/apply-{env}.yml`, gated to run only on merge to `main`, per environment, with GitHub Environment protection rules requiring manual approval for `staging` and `production`.
- [ ] Task 6 (AC: 9): Add `.github/CODEOWNERS` and `.github/PULL_REQUEST_TEMPLATE.md` (infra-change checklist).
- [ ] Task 7 (AC: 11, 12): Merge the PR, let the gated apply run against `dev`, and capture the pipeline log plus the plan output attached to the PR as the verification evidence for "nothing has been built yet."
