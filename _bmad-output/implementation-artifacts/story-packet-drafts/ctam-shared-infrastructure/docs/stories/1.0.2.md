# Story 1.0.2: The network and the Kubernetes cluster are built and checked (development environment)

Status: ready-for-dev

## Story

As a **platform engineer**,
I want the resource group, network, and Kubernetes cluster built through Terraform in the UK South region,
so that **there is a proven, resilient place for every CTAM Pathfinder service to run, checked and working before anything is deployed onto it**.

## Acceptance Criteria

1. Given the repository and its change-management process are set up as described in Story 1.0.1, when the engineer adds the networking and cluster setup and applies it to the development environment, a resource group, virtual network, and subnets are created in the UK South region.
2. A Kubernetes cluster is built with its worker machines spread across multiple availability zones for resilience.
3. The cluster and machine sizes match the agreed early-phase baseline.
4. Engineers can retrieve access to the cluster through their own Azure sign-in rather than a shared static password.
5. Given the cluster has been built, when the engineer checks it by running a standard cluster-status command, every node reports as ready and is spread across the different availability zones.
6. A simple throwaway test workload can be started on the cluster and successfully respond to a request sent to it from inside the cluster.
7. This check is written down as a repeatable verification step that can be run by hand or as part of the pipeline — so the cluster is proven working, not just assumed to be.

## Tasks / Subtasks

- [ ] Task 1 (AC: 1): Write `terraform/modules/network/` (resource group, VNet, subnets, UK South). Run `terraform plan` against dev before the module exists to capture the red (resources absent / plan errors), then apply and capture green.
- [ ] Task 2 (AC: 2, 3): Write `terraform/modules/aks/` — cluster + multi-AZ node pool sized to the agreed early-phase baseline. Cite the baseline source rather than picking a size unprompted (R5) if it isn't already pinned somewhere in the planning artifacts.
- [ ] Task 3 (AC: 4): Configure Azure AD-integrated cluster access (`kubelogin` / Azure RBAC for Kubernetes) so `az aks get-credentials` + Azure sign-in replaces any static kubeconfig password.
- [ ] Task 4 (AC: 5, 6, 7): Write `verification/aks-nodes.sh` (per `_arch/architecture/repo-structure.md`'s naming for this exact check) — first run it against a state with no cluster to capture the red (script fails, no nodes), then after apply, capture the green: `kubectl get nodes` shows every node `Ready` and zone-spread, and a throwaway pod answers a request from inside the cluster.
- [ ] Task 5 (AC: 7): Wire `verification/aks-nodes.sh` into the CI pipeline (or document the by-hand invocation) so the check is repeatable, not a one-off.
